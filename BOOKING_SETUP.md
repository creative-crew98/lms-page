# Simple consultation slots

Google Calendar has been removed from the form. After all eight answers save, users pick a date and one available time, then confirm. Availability covers the next 14 calendar days, Monday-Saturday, in Asia/Kolkata. Times: 10:30 AM, 12:00 PM, 1:30 PM, 3:00 PM, 4:30 PM, 6:00 PM. Sundays, past times, and booked slots are excluded. The UI refreshes availability every 20 seconds while visible. Confirming rechecks the slot under the Apps Script lock, so a stale browser cannot double-book it.

Paste the entire updated google-apps-script/Code.gs into your existing Google Sheet Apps Script project. Update the existing web-app deployment: Deploy > Manage deployments > Edit > Version: New version > Deploy. Keep the same /exec URL used by Form.tsx. Run setup once if you have not configured your sheet. The script finds its booking and status columns by header and adds any missing headers after the existing columns, preserving existing lead data. Lead-ID retries update/return the same booking instead of inserting duplicates. One reservation is allowed per date/time across this script's Leads sheet. Manual edits or other scripts that bypass its lock must not create reservations.

Bookings do not create a Google Calendar event or Google Meet link. The selected date and time are recorded in the same lead row as contact details and all answers. This is a static exported website using the existing Google Apps Script web app; no backend is copied into the CRM. The Apps Script update must be deployed before the new booking UI can fetch availability or reserve times.

## CRM lead sync

In Apps Script, open **Project Settings > Script properties** and add `CRM_LEAD_RECEIVER_URL` with `https://YOUR_PROJECT_REF.supabase.co/functions/v1/lead-ingest` (or the configured `super-worker` function), and `CRM_LEAD_INGEST_SECRET` with the same server secret saved in Supabase. Do not put the database service-role key here. Run `setup()` once from the spreadsheet's Apps Script project: it sets the spreadsheet timezone to India, formats lead timestamps as 12-hour time with AM/PM, corrects legacy rows written one column off when their role answer is recognizable, installs a one-minute CRM sync trigger, and immediately processes eligible rows. New form values are matched to sheet headers, so the message and answers save under their labeled columns. It records `Delivered to CRM` or a `Pending - ...` reason in the `CRM delivery` column. Existing rows with a blank delivery status are picked up too; incomplete contact/questionnaire rows remain queued until their submission stage is `completed` or `booked`. If you already ran setup before this update, run `setup()` again to apply the timezone/display format, correct recognizable misaligned rows, and reinstall the trigger. The Apps Script CRM delivery code takes effect after updating the web app deployment.
